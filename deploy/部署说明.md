# 让网站在任何地方都能打开

## 先想清楚一件事

"随时能访问" 需要两个东西，缺一不可：

1. **一台一直开着的机器**在跑程序
2. **一个公网入口**让别人能连进来

而摄像头有个硬约束：**它必须和采集程序在同一台机器上**。
所以"网站放云上"和"摄像头在现场"这两件事，早晚要拆开。

你现在还在用视频调试，**没有摄像头**，所以可以直接把整个程序放到云服务器上——
这是最省事的阶段，先把它跑起来。

---

## 三个阶段，不要一步到位

| 阶段 | 你现在的情况 | 做法 | 成本 |
|---|---|---|---|
| **A. 现在的做法** | 笔记本上 `python3 run.py` | 只能同 WiFi 访问 | ¥0 |
| **B. 组员随时能看**（推荐先做） | 还没有摄像头 | 云服务器跑整个程序，上传视频看结果 | ¥10–30/月 |
| **C. 接真摄像头** | 现场有摄像头 | 现场机器采集 + 只把状态推到云上 | 同上 + 一台现场机 |

**别跳过 B 直接做 C。** B 能让你和组员先把产品用起来，验证"这个东西值不值得做"，
而这恰恰是现在最该验证的事。

---

## 方案 B：云服务器（推荐）

### 1. 买什么

国内随便一家轻量应用服务器：**2 核 2G、Ubuntu 22.04**，学生价通常 ¥10–30/月。
1 核 1G 也能跑（视频是 960×540，够用），但编码解码会卡，别省这十块钱。

> 不需要备案（用 IP 访问）；想要域名和 HTTPS 才需要。

### 2. 装什么

```bash
sudo apt update && sudo apt install -y python3 python3-pip
cd /opt && sudo mkdir seat-assistant && sudo chown $USER seat-assistant
# 把项目传上去（scp / rsync / git）
cd /opt/seat-assistant
pip3 install opencv-python-headless numpy
```

注意用 **`opencv-python-headless`**：服务器没有图形界面，装带 GUI 的版本会报
`libGL.so.1 not found`。

### 3. 先手动跑一次

```bash
python3 run.py --source none --host 0.0.0.0 --port 8000 --admin-token 你的随机串
```

浏览器开 `http://服务器IP:8000`，能打开就说明通了。
打不开先去云厂商控制台的**安全组**里放行 8000 端口（这一步最容易漏）。

### 4. 让它一直跑

```bash
sudo cp deploy/seat-assistant.service /etc/systemd/system/
sudo useradd -r -s /usr/sbin/nologin seat || true
sudo chown -R seat:seat /opt/seat-assistant
sudo systemctl daemon-reload
sudo systemctl enable --now seat-assistant
journalctl -u seat-assistant -f     # 看日志
```

### 5. 访问

`http://服务器IP:8000` —— 直接把链接发组员，微信里点开就行。

## 安全：三个必须做的设置

### ① 一定要设 `--admin-token`

标定页、摄像头画面、上传接口都是管理员功能。
如果不设 token，从服务器本机访问的人（以及被隧道代理伪装成"本机"的任何人）
都能直接打开。

设了之后，管理员功能要这样访问：

```
http://服务器IP:8000/calibrate?token=你的随机串
```

普通页面（座位地图、空态）不需要 token，组员直接看就行。

### ② 不要把摄像头画面暴露出去

代码里 `/api/snapshot.jpg` 和 `/api/camera.jpg` 本来就只对管理员开放。
上了公网以后，**任何情况下都不要改成公开**——那是会拍到人的画面。

### ③ 上传目录会越积越大

`data/uploads/` 每传一个视频就存一份。定期清：

```bash
find /opt/seat-assistant/data/uploads -mtime +7 -delete
```

## 方案 C：接真摄像头以后

摄像头在自习室，服务器在云上，两边必须分工：

```
[自习室现场]                      [云服务器]
 摄像头 → 树莓派/旧笔记本            FastAPI + 数据库 + 网页
  只做识别，画面不出设备      ──►     只收 JSON：{"seat":"A1","state":"free"}
```

这样：
- 画面永远不出场馆（隐私叙事成立，也是说服图书馆的关键）
- 学校网络不需要公网 IP
- 带宽几乎为零（一间房一小时 < 1 MB）

**这个"边缘推状态"模式我现在还没写**，但架构上是留好的：
`app/` 里的观测器和状态机可以直接复用到边缘端，云端只需要一个接收接口。

## 备选：内网穿透（不买服务器）

如果你只是想让 **3 个组员**临时看一下，不想花钱：

| 工具 | 免费额度 | 优点 | 缺点 |
|---|---|---|---|
| **Tailscale** | 个人免费，3 用户 | 私有网络，不暴露公网，5 分钟配好 | 国内偶尔连不上，依赖中继 |
| **Cloudflare Tunnel** | 免费 | 自动 HTTPS，自带域名 | 国内速度一般，需要一个域名 |
| **frp + 便宜 VPS** | VPS 钱 | 国内最稳 | 要自己配 |

**Tailscale 的做法**：在你那台常开的电脑和 3 个人手机/电脑上都装 Tailscale，
登录同一账号，然后用 `http://<你的设备名>:8000` 访问。
不产生公网地址，安全上最省心。

代价是：**你的电脑必须一直开着**。合盖休眠 = 网站下线。

## 一句话建议

- **现在**：花 ¥10–30 买台轻量服务器，按上面的步骤部署，`--source none`，用视频跑。
- **装机那天**：现场放一台树莓派（¥700，功耗 5W，可以常年开），把"只推状态"的模式接上。
- **别做的**：不要用学校公网 IP 做端口映射，不要在校园网里开热点暴露服务，
  不要把 `--admin-token` 留空后放到公网。
