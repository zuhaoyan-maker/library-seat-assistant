# 15 座自习室试点执行手册

> 目标：两周内拿到"能不能用"的答案，而不是"能不能做"。
> 判断标准只有一个 —— 每天人工核对，座位级准确率能否稳定在 90% 以上。

---

## 0. 试点前先明确的一件事

你的产品**目前对图书馆没有直接好处**，对同学有好处。所以布点谈话时，
不要只讲"帮同学找座位"，要同时给出这两样东西：

- **区域利用率报表**：哪个时段这个房间几乎空着（可以考虑关掉省电/合并自习区）。
- **占座数据**：多少人放了书就走（这恰好是图书馆最头疼的问题）。

一页纸的数据承诺 + 可随时撤除的支架，比任何演示都有说服力。

## 1. 机位（这是试点成败的第一因素）

15 个座位，**一台相机足够**，不要买第二台。

### 1.1 站哪儿

```
        ┌──────────────────────────────┐
        │  ▢A1  ▢A2  ▢A3 │ ▢A4  ▢A5    │
        │  ▢A6  ▢A7  ▢A8 │ ▢A9  ▢A10   │
        │  ▢A11 ▢A12 ▢A13│ ▢A14 ▢A15   │
        └───────────┬──────────────────┘
                    │
              [ 支架 ]  ← 后排角落，高 2.4–2.7m
                俯角 ≈ 40°
```

**规则：**

| 项 | 要求 | 原因 |
|---|---|---|
| 位置 | **最后一排的角落**（或门口一侧墙角） | 视线沿排间空隙穿过，每个人至少露头肩；不会被自己这一排挡住 |
| 高度 | 镜头 **2.4–2.7m** | 低于 2.2m 容易被走动的人挡住，高于 2.8m 只看到头顶和桌面 |
| 俯角 | **35°–50°** | 太平会拍到脸且遮挡严重；太陡看不到人是否坐着 |
| 朝向 | 斜向 45° 对房间，**不要正对窗户** | 逆光会让靠窗座位过曝（这片恰好是最抢手的座位） |
| 距离 | 相机到最远座位 ≤ 7m | 15 座的小房间一般 4–6m，2.8mm 镜头绰绰有余 |

**用手机先试**：站在候选位置举到 2.5m 高，拍一张照，数一数能看清几个座位、
有没有被书架/柱子/人挡住。看不清就别装。

### 1.2 支架怎么选

| 方案 | 高度 | 价格 | 说明 |
|---|---|---|---|
| **摄影灯架 + 横臂**（推荐） | 2.6m | ¥90–160 | C 型灯架最稳，1/4 螺丝直接接相机夹具 |
| 三脚架 + 中轴升高 | 1.6–1.9m | ¥80–200 | 高度通常不够，但可放在桌上补足 |
| 落地投影支架 | 2.0m | ¥60–120 | 便宜，底盘轻，需配重 |
| 毕业设计级 | 2.5m | ¥20 | 木条 + 扎带，能用但不体面 |

**必须做的三件事：**

1. **配重**：沙袋或两本厚书压住脚架。被碰一下，整套座位多边形就错位了。
2. **标记位置**：地面贴一小块胶带标记三个脚的位置 —— 移动后能立刻发现。
3. **线走墙边**：电源线和数据线贴地走墙脚，用线槽胶带压住。
   **过道中间拉一根线是安全事故**，也是图书馆最容易拒绝你的理由。

### 1.3 供电与传输

- **有线优先**：USB 线超过 5m 会掉帧/不认设备，用 **5m 有源延长线**（¥50–70）。
- **不想拉线**：65W PD 充电宝（20000mAh）可以给相机供电 8 小时以上，
  笔记本另算。适合"先试一周"的场景。
- **想更专业**：换成 PoE 网络相机 + 一根网线，支架上只要走一根线。
  但试点阶段没必要，USB 相机足够。

### 1.4 隐私布置（顺手就能做）

- 支架上贴一张 A6 卡片：
  > 「本设备仅统计座位占用情况，画面在本机处理，不存储、不上传、不识别个人。」
- 相机**俯拍**本身就天然避开人脸 —— 画面里主要是桌面、椅面和头顶。
- 空镜和调试画面只在本机看得到（服务端已限制为非本机不可访问）。

## 3. 第一周：把系统跑起来

### Day 1 — 谈话 + 勘察
- [ ] 找管理员/辅导员说明：只统计座位、不录像、可随时撤除、支架不破坏建筑
- [ ] 现场拍照，画一张 15 座的平面草图，标座位编号
- [ ] 站到候选机位举手机拍照，确认能看清 15 个座位
- [ ] 确认插座位置、WiFi 名称、有没有监控死角要求

### Day 2 — 安装 + 标定
- [ ] 支架就位，配重、贴地面标记、走线
- [ ] `python3 run.py --source 0`
- [ ] 打开 `/calibrate`：**等房间完全空下来**，点「拍空镜」
- [ ] 逐个座位点 4 个角。框要**贴合椅面 + 桌子前缘**，不要画得过大
- [ ] 保存，回首页看 15 个格子是否正确

> 画框要点：框太大 → 变化比例被稀释，人坐着也可能判成"空"；
> 框太小 → 人稍微侧身就漏出框外。**贴着椅面和桌沿画一圈**最稳。

### Day 3 — 调阈值
- [ ] 打开 `/calibrate`，看「实时判分」面板
- [ ] 让同学分别做到：正常坐着 / 起身离开 / 放个书包 / 空着
- [ ] 记录四种情况下同一个座位的大致分值，确认能分开
- [ ] 分不开就调 `SEAT_PERSON_RATIO` / `SEAT_BELONGING_RATIO`

典型经验值（仅供参考，必须现场校准）：

| 状态 | 判分 |
|---|---|
| 空 | 0.00–0.04 |
| 书包/外套 | 0.08–0.20 |
| 有人坐着 | 0.25–0.55 |
| 有人 + 椅子被拉出 | 0.4–0.7（会误判邻座，需观察） |

### Day 4–7 — 无人值守运行
- [ ] 保持笔记本常开（关掉休眠：`系统设置 → 锁定屏幕 → 关闭显示器后进入睡眠 = 永不`）
- [ ] 每天早晚各看一次 `/api/state`，确认相机没有掉线
- [ ] 记录第一次"误判"发生在什么情况（这是最有价值的信息）

## 4. 第二周：采集与验收

### 每天三次人工核对（每次 3 分钟）

| 时间 | 实际空位数 | 系统空位数 | 错判的座位 | 当时情况 |
|---|---|---|---|---|
| 10:00 | | | | |
| 15:00 | | | | |
| 20:00 | | | | |

连续 7 天。第 8 天算三个数：

- **座位级准确率** = 判对的座位次数 / 总次数，目标 **≥ 90%**
- **空位数误差** = |实际 − 系统|，目标 **≤ 2**
- **误报为空**（有人却显示空）的次数 —— 这个最伤用户，目标 **≤ 1 次/天**

### 拿到数据后，做一次"用户测试"

找 5 个同学，把网址发给他们，只问两个问题：

1. 你会不会在出发前打开它？
2. 它哪里让你不敢信？

第 2 个问题的答案决定下一步做什么，比你自己想的功能清单准。

## 5. 常见误判与对策

| 现象 | 原因 | 处理 |
|---|---|---|
| 白天靠窗座位全变"占用" | 阳光移动，画面整体变化 | 拍空镜时选**阴天或晚上**；或把靠窗那片单独晚一点拍一次 |
| 椅子被拉出来后一直"暂离" | 椅子位置变了，与空镜不同 | 把椅子推回原位再拍空镜；或缩小座位框到桌面 |
| 有人坐着却显示"空" | 座位框画太大 / 人被前面挡住 | 缩小框；调整机位提高俯角 |
| 邻座有人，本座显示"暂离" | 人体溢出到相邻框 | 已有 14% 腐蚀保护；仍出现就拉开框的间距 |
| 全部变"未知" | 相机掉线/休眠 | 检查电源、关闭系统休眠、看日志 |
| 忽空忽占反复跳 | 阈值卡在临界 | 加大 `SEAT_ON_SEC`（默认 15s）到 25s |

## 7. 什么时候可以进下一个房间

满足全部三条再扩：

- [ ] 连续 7 天座位级准确率 ≥ 90%
- [ ] 有 ≥ 20 个真实用户在用，且能说出"我每周会用几次"
- [ ] 图书馆主动问"能不能也给 X 房间装一个"

如果第三条没出现，说明价值还没被感知 —— 别急着加功能，
先回去问那 5 个同学：他们到底在什么时刻、因为什么原因打开了这个页面。
